# 함께 만드는 법

이 문서는 git을 처음 쓰는 선생님을 생각하고 썼습니다. 명령은 모두 `lessons/` 폴더 안에서 돌립니다.

## 1. 차시 하나 고치기·더하기

폴더 이름이 곧 차시의 id입니다. id는 `학기/단원/묶음` 꼴이고, 묶음은 차시 번호입니다.

예를 들어 5학년 2학기 1단원 3~4차시는 `content/5-2/1/03-04/` 폴더이고, 명세는 그 안의 `lesson.yaml` 입니다. 사이트 주소도 `/5-2/1/03-04/` 가 됩니다. 묶음 id는 차시표(`content/registry.yaml`)에 이미 적혀 있으므로 거기 있는 이름으로 폴더를 만듭니다.

새 차시는 이렇게 시작합니다.

1. 차시표에서 묶음 id를 찾습니다. 없으면 차시표에 먼저 더합니다.
2. `content/<학기>/<단원>/<묶음>/` 폴더를 만들고, 그 안에 `docs/template/lesson.yaml` 을 `lesson.yaml` 이라는 이름으로, `docs/template/media/` 폴더를 `media/` 로 복사합니다.
3. 맨 위의 `id` 를 폴더와 같게 고칩니다.
4. 칸마다 달린 주석을 읽으며 채웁니다. 다 쓴 칸의 주석은 지워도 됩니다. 본보기의 그림 두 개(`example-diagram`, `example-photo`)는 자리만 잡아 둔 것입니다. 실제 그림으로 바꾸거나, 지우고 그 그림을 가리키는 칸도 함께 지웁니다.
5. `npm run check` 로 검사하고, `npm run dev` 로 화면을 봅니다.

고칠 곳이 있으면 `npm run check` 가 몇째 줄의 어느 칸인지와 어떻게 고칠지를 한 줄씩 알려 줍니다. 명세 파일 이름은 소문자 `lesson.yaml` 이어야 합니다. `lesson.yml` 이나 `Lesson.yaml` 은 읽히지 않고 검사가 실패합니다.

## 2. YAML에서 자주 틀리는 다섯 가지

명세는 YAML이라는 글 형식으로 씁니다. 대부분은 `칸 이름: 값` 꼴이라 그대로 읽히지만, 다섯 경우에는 값이 엉뚱하게 읽히거나 파일이 아예 읽히지 않습니다.

1. **글 안의 콜론+빈칸.** `title: 질문: 누가 만들었을까` 는 읽히지 않습니다. 글 전체를 큰따옴표로 감쌉니다: `title: "질문: 누가 만들었을까"`
2. **따옴표로 시작하는 글.** `text: "고인돌"이라고 부릅니다` 는 읽히지 않습니다. 글 전체를 다시 감쌉니다: `text: '"고인돌"이라고 부릅니다'`
3. **값 뒤의 ` #`.** `caption: 덮개돌 #1` 에서 ` #` 뒤는 주석으로 버려집니다. 검사가 막아 주지만, 글에 #이 들어가면 큰따옴표로 감싸고 주석은 윗줄에 씁니다.
4. **탭 들여쓰기.** 들여쓰기는 빈칸 두 개씩입니다. 탭을 쓰면 읽히지 않습니다.
5. **true/false 자리의 O·X.** OX 문항의 답은 `answer: true` 나 `answer: false` 로 씁니다. `answer: O` 는 글로 읽혀 형식 오류가 납니다.

메모장으로 고칠 때는 인코딩을 UTF-8로 골라 저장합니다. 다른 인코딩으로 저장하면 한글이 깨집니다.

## 3. 그림을 넣기 전에

남의 사진은 이용 조건을 확인한 뒤에만 넣습니다. 저장소에 올리는 순간 공개되기 때문입니다.

쓸 수 있는 조건은 저작권 없음(퍼블릭 도메인)·CC0, 공공누리 제1유형, CC BY, CC BY-SA 넷입니다. 같은 그림을 공공누리 제1유형이나 퍼블릭 도메인으로 구할 수 있으면 그쪽을 씁니다. CC BY-SA 그림은 자르거나 본뜨지 않고 그대로 씁니다 (`change: none`).

예를 들어 국립중앙박물관 소장품 사진은 소장품 페이지에서 공공누리 유형을 확인하고, 제1유형이면 그 페이지 주소를 `source_url` 에, 확인한 날을 `checked` 에 적습니다. 제목(`credit.title`)에는 소장품 이름을 적습니다. `GMJ 0154.jpg` 같은 파일 이름을 적으면 검사가 실패합니다.

그림마다 다섯 가지를 확인합니다.

- **이용 조건**: `credit.licence`. 직접 그린 것만 `original` 입니다. 위키백과·블로그·영상에서 가져온 그림은 쓰지 않습니다. 위키미디어 공용은 쓸 수 있습니다.
- **출처 주소**: `credit.source_url`. 원본이 실린 페이지 주소입니다.
- **확인한 날**: `credit.checked`. 원본 페이지에서 이용 조건을 본 날입니다.
- **1MB 이하**: 넘으면 검사가 실패합니다. 사진은 긴 변 1600px 정도로 줄여 저장합니다.
- **파일 이름**: 영문 소문자, 숫자, 하이픈만 씁니다. 예: `media/pottery-amsa.jpg`

사람 얼굴이 알아볼 수 있게 나오는 사진은 `person: true` 로 적고 초상권을 확인한 내용을 `credit.note` 에 씁니다.

## 4. 교과서 문장·활동·예시 답을 옮기지 않습니다

교과서에서 가져오는 것은 단원명, 차시 번호, 쪽수뿐입니다. 이 셋은 차시표에만 적습니다.

예를 들어 교과서의 발문을 말만 조금 바꿔 옮기거나, 지도서의 예시 답을 학습지 풀이에 적는 것도 옮긴 것입니다. 같은 활동을 같은 차례로 묻는 것도 마찬가지입니다. 교과서를 덮고 우리 말로 새로 씁니다.

YAML 주석과 검수 메모에도 교과서 문장을 적지 않습니다. 겹친 곳은 "교과서 8쪽, 14자"처럼 쪽수와 길이로만 적습니다.

## 5. 이용 조건에 동의합니다

PR을 올리면 기여한 글과 그림은 CC BY-NC-SA 4.0으로, 코드는 MIT로 공개하는 데 동의한 것으로 봅니다. 자세한 범위는 [`LICENSE-CONTENT.md`](LICENSE-CONTENT.md)와 [`LICENSE`](LICENSE)에 있습니다.

## 6. 검수 기록

명세는 검수 다섯 가지를 거쳐야 공개됩니다: 사실 대조, 베끼기 검사, 문장 다듬기, 화면·인쇄 점검, 날쌤 승인. 기록은 손으로 적지 않고 도구로 적습니다.

```sh
npm run sign -- 5-2/1/01 voice --by "별명"
npm run sign -- 5-2/1/01 check f3 --by "별명"
```

기록에는 검수한 내용의 지문이 함께 적힙니다. 검수한 뒤에 한 글자라도 고치면 그 기록은 없는 것이 되고, 다시 검수합니다.

- `--by` 에는 공개해도 되는 별명을 적습니다. 실명, 학교, 이메일은 적지 않습니다. AI가 검수했으면 `ai:` 로 시작하는 이름을 씁니다.
- 날쌤 승인과 공개(`status: published`)는 날쌤만 적습니다.
- 베끼기 검사 기록은 날쌤이 PR에서 적습니다. 비공개 교과서 자료가 있어야 검사할 수 있기 때문입니다.

그래서 비공개 자료가 없으면 두 가지가 보입니다. 둘 다 정상입니다.

- `git push` 할 때 "베끼기 검사를 건너뜁니다" 한 줄이 나오고 그대로 올라갑니다.
- `npm run check` 와 PR의 검사에 "베끼기 검사 기록이 없습니다"가 알림으로 나옵니다. 고칠 것이 아닙니다.

## 7. 공개된 차시를 고칠 때

공개된 차시는 종이에 QR로 박혀 있습니다. 고치는 동안에도 주소가 사라지지 않게 한 PR 안에서 순서대로 합니다.

1. 고치는 차시의 `status` 를 `draft` 로 되돌립니다. 그 차시를 가리키는 묶음(같은 단원의 뒤 묶음, 특히 단원 정리 묶음)도 같은 커밋에서 `draft` 로 되돌립니다.
2. 내용을 고칩니다. 사실을 고쳤으면 `corrections` 에 날짜와 고친 내용을 한 줄 적습니다. 안내 페이지에 보입니다.
3. 바뀐 검수를 다시 받습니다. `npm run check` 가 초안마다 "공개까지 남은 것"을 한 줄로 알려 줍니다 (어느 검수와 어느 사실의 확인이 남았는지).
4. 날쌤이 다시 `published` 로 적습니다.

가리키는 묶음만 함께 내린 경우, 빌려 온 사실·그림·카드가 그대로이면 그 묶음의 검수 기록은 그대로 맞습니다. 그때는 `status` 만 다시 `published` 로 적습니다.

## 막혔을 때

`npm run check` 의 글로 풀리지 않으면 깃허브 이슈에 그 글을 붙여 올려 주세요. 형식과 각 담당의 약속은 [`docs/CONTRACT.md`](docs/CONTRACT.md)에 있습니다.
