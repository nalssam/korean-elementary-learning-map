# 계약서 검토에서 정한 것

계약서 초안을 네 관점(명세를 쓰는 사람 A, 생성기를 만드는 사람 G, 오래 관리할 사람 M, 출처와 검수 P)에서 검토했습니다. 제안은 대부분 그대로 받아들였습니다. 여기에는 **받아들이지 않았거나 고쳐서 받아들인 것**과 그 까닭을 한 줄씩 적습니다. 번호는 검토 기록의 번호입니다.

## 서로 달랐던 제안 가운데 고른 것

| 무엇 | 고른 것 | 까닭 |
|---|---|---|
| 두 차시 묶음의 차시 경계 (A0, G5) | 흐름 단계에 `lesson` 을 적는다 (A0) | "정리 다음 도입이면 다음 차시"로 짐작하는 방식(G5)은 정리가 없는 차시를 나누지 못하고, 어디에서 끊는지가 파일에 보이지 않습니다. |
| 같은 값을 두 번 적던 칸 (A10, M5, G21) | 명세에는 `id` 만 남기고 차시 번호·쪽수·성취기준·시간은 차시표와 계산으로 | 견주려고 두 번 적게 하는 칸은 틀릴 자리만 늘립니다. |
| 성취기준을 어디에 적나 (A10, G21) | 단원에 적는다. 묶음의 `standards` 는 선택 | 확인된 것이 단원과 성취기준의 짝뿐입니다. 묶음마다의 짝을 지어내지 않습니다. |
| 방탈출과 3D (A1, A5, G6, M3) | skip·planned 만 받는다 | 생성기가 없는데 꼴을 정하면 아무도 써 보지 않은 형식이 굳습니다. 밑그림은 `docs/ROADMAP.md` 에 둡니다. |
| 읽는 글 (A4, G9) | 둘 다. 읽기 자료 `passages` 와 짧은 글 블록 `note` | 수업 화면과 학습지가 같이 쓰는 긴 글과, 학습지에만 있는 한 줄은 쓰임이 다릅니다. |
| 카드 인쇄 (A9, G4) | 양면, 한 면에 8장, 뒷면은 열을 바꿔 (G4) | 접어 붙이는 방식(A9)은 한 쪽에 4장만 나오고 풀칠이 듭니다. 어긋남은 뒷면의 여백으로 받습니다. |
| 지도에 놓는 활동의 이름 (A2, G10) | `place` | 지도가 아닌 그림 위에도 놓습니다. A2 의 `why` 와 활동마다의 `facts` 는 받아들였습니다. |
| 상태 값 (M2, P9, G21) | `draft`, `published` | 중간 단계는 `reviews` 가 말해 줍니다. 이름은 사이트에 보이는 뜻 그대로 `published` 입니다. |
| 점수를 끄는 기준 (A13, P4) | `sensitivity.level` 이 none 이 아니면 끈다 (P4) | 전쟁을 다루는 care 차시도 피해를 점수로 세지 않아야 합니다. |
| 사실을 가리키는 칸 이름 (A12, P2) | 어디서나 `facts` (목록) | `fact` 와 `facts` 가 섞이면 오타 난 쪽이 조용히 빠집니다. |
| 출처 표시 (M8, P3) | 손으로 적는 `credit.line` 을 없애고 `creditShort()`·`creditFull()` 이 만든다 | 손으로 적은 줄은 이용 조건과 어긋나도 잡을 수 없습니다. |
| 흐름의 수업 화면 범위 (G20, M7) | `[첫 장, 끝 장]` (M7) | `"1-3"` 은 따옴표를 빼먹으면 숫자나 다른 글로 읽힙니다. 차시표의 `pages` 와 같은 꼴입니다. |
| 오류 문구 (A20, G11, M6) | 로더가 한국어로 풀어 준다 (M6) | zod 의 한국어 문구는 "잘못된 입력"처럼 고칠 길을 알려 주지 못했습니다. 전역 설정은 Astro 가 쓰는 zod 에도 번집니다. |

## 받아들이지 않은 것

| 제안 | 까닭 |
|---|---|
| A1 방탈출의 방·퍼즐 형식을 지금 넣기 | 생성기가 없습니다. `docs/ROADMAP.md` 에 밑그림으로 둡니다. |
| A5 3D 의 `module`·`url` 형식을 지금 넣기 | 위와 같습니다. |
| M5 명세에서 `id` 도 빼기 | 한 줄이고, 폴더를 복사해 새 차시를 만든 사람에게 "id 를 고치라"고 알려 주는 자리입니다. |
| M7 `terms.new` 를 `new_terms` 로 | 뜻이 같고, 바꿀 까닭이 되는 생성기가 없습니다. |
| M8 `credit.version` | CC 의 판은 주소(`licence_url`)에서 읽습니다. 같은 것을 두 칸에 적지 않습니다. |
| M9 `SITE.mediaHosts` (바깥 그림 주소의 예외 목록) | 바깥 주소의 그림(`media.url`)을 아예 받지 않기로 해서 예외가 없습니다. |
| M16 처음부터 `/social` 에 배포 | 배포 경로는 날쌤이 정합니다. 계약서에는 "한 번 정하면 바꾸지 않는다"만 적었습니다. |
| P5 검수 종류 `rights` | 검수 종류는 다섯으로 두고, 그림의 이용 조건 확인은 베끼기 검사(originality)가 함께 합니다. 그림마다 `credit.checked` 가 남습니다. |
| P13 공공누리 제0유형 | 있는지 확인하지 못했습니다. 확인되면 선택값을 더합니다 (형식의 판을 올리지 않는 변경입니다). |
| G7 QR 주소를 `Astro.site` 로 | Node 와 Python 에서도 같은 주소가 나와야 해서 `absoluteUrl()` 하나로 만듭니다. |
| G16 만들지 않는 까닭(`reason`)·계획(`idea`)을 교사가 읽는 글로 | 사이트에 보여 주지 않는 제작 기록입니다 (A19). 대신 `recordStrings()` 로 따로 뽑습니다. |
| A8 학습지의 고르기(`choices`) 블록을 남기기 | 확인 퀴즈의 문항을 그대로 찍는 `quiz` 블록으로 바꿨습니다. 답이 없는 문항을 따로 적지 않습니다. |
| 영상(`video`) | 띄우는 장도 생성기도 없습니다 (A14, G12, M3). |

| 제안 | 어떻게 | 까닭 |
|---|---|---|
| A0 `/slides/?from=4` | `flowByLesson()` 의 `firstSlide` 와 `/slides/#5` | 정적 사이트에서는 주소 뒤의 `#` 이 더 단순하고, 장 번호로 여는 약속(G7)과 하나로 합쳤습니다. |
| A0 퀴즈 문항의 `lesson` | 적지 않으면 마지막 차시. `quizByLesson()` | 만드는 쪽이 저마다 짐작하지 않게 했습니다. |

| A3 단원 덱 | `collect` 는 단원 정리 묶음에서만, no_play 묶음은 모으지 않음 | P4 의 "no_play 차시의 카드를 가져가지 않는다"와 합쳤습니다. |

## 검토에 없었지만 더한 것

- `CONTENT_DIR`: 시험이 가짜 차시표를 읽을 수 있게 했습니다. 두 차시·단원 정리·no_play 묶음을 담당마다 시험할 수 있습니다.
- `recordStrings()`, `quizByLesson()`, `slideNotes()`, `answerText()`, `worksheetKey()`, `splitFrame()`, `reviewState()`, `pptxFile()`, `mediaFile()`, `unitPages()`: 두 담당 이상이 같은 규칙으로 같은 값을 내야 하는 자리입니다.
- `astro dev` 는 늘 초안을 보여 줍니다 (`astro.config.mjs`).
- `tests/contract/fixtures/site`: 틀과 도우미를 실제로 빌드해 보는 작은 사이트입니다.
- 고인돌 초안에 `assets.papercraft.texts` 를 적었습니다. 전개도 모듈 안에 문장을 두지 않기로 해서, 차례 카드 네 장의 문장이 명세로 왔습니다 (수업 화면 6번 장과 같은 문장입니다).

## 합친 계약서를 다시 검토하고 정한 것

네 관점이 합친 계약서를 써 보고 다시 낸 문제들입니다. 대부분은 그대로 고쳤습니다. 여기에는 **서로 달랐던 제안 가운데 고른 것**과 **받아들이지 않았거나 고쳐서 받아들인 것**만 적습니다.

### 서로 달랐던 제안 가운데 고른 것

| 무엇 | 고른 것 | 까닭 |
|---|---|---|
| 공개된 차시를 고칠 때의 `status` (A: 그대로 둔다, P: draft 로 되돌린다) | draft 로 되돌린다. 고치기부터 다시 공개하기까지 한 PR | published 인 채로는 빌드와 `npm run dev` 가 멈춰서, 다시 받아야 하는 화면·인쇄 점검을 할 수 없습니다. 지문과 남은 검수를 묻는 함수는 어느 쪽이든 읽히게 했습니다. |
| YAML 주석을 지문에 넣을지 (A: 넣는다, P: 넣지 않는다) | 넣지 않는다. 지문은 값만 본다 | 주석 한 줄에 검수 다섯 가지가 모두 무효가 되고, 주석을 지우는 도구 하나가 모든 기록을 지웁니다. 주석의 베끼기는 올리기 전 검사(`pre-push`)가 기록과 상관없이 다시 봅니다 (계약서 13절). |
| 차시표의 `focus` (M: 사이트에 찍지 않는다, P: 차시표에 베끼기 검사 기록을 둔다) | 둘 다 | 사이트에 찍지 않아도 저장소는 공개입니다. 사실 대조를 거치지 않은 문장을 "교사가 검수한 자료" 아래에 싣지 않는 것과, 교과서 차시 제목을 옮기지 않았는지 보는 것은 다른 일입니다. |
| PDF·PPTX 를 다시 만들지 정하는 입력 (M: `inputFiles(id)` 와 폴더 목록, G: 찍는 HTML 과 그것이 부르는 파일) | 찍는 HTML 과 그것이 부르는 파일 (G) | 목록은 빠뜨릴 수 있고 실제로 빠져 있었습니다 (단원 덱, 차시표, `SITE_URL`). 찍는 것 자체를 입력으로 삼으면 빠질 수 없습니다. |
| 인쇄 틀이 생기기 전에 페이퍼크래프트 담당이 무엇에 기대는가 (G: 뼈대를 미리 넣는다 / 대역으로 시험한다) | 뼈대를 미리 넣는다 | 두 담당이 같은 props 와 치수를 따로 짐작하지 않습니다. 뼈대는 계약 시험(`frame.test.ts`)이 빌드해 봅니다. |

### 받아들이지 않은 것

| 제안 | 까닭 |
|---|---|
| 주석을 `lessonSeal()` 에 넣기 | 위 표. 대신 13절에 "지문은 값만 본다, 주석에는 자료의 문장을 옮기지 않는다, 올릴 때 다시 검사한다"를 적었습니다. |
| `inputFiles(id)` 를 `lib/content.ts` 에 더하기 | 위 표. 쓰는 곳이 없어졌습니다. |
| `npm run sign -- registry originality` | 베끼기 검사의 통과 기록은 검사 도구가 적기로 해서 (`check:originality --record`), 서명 도구에 차시표용 명령을 더하지 않았습니다. |
| 글꼴을 정적 부분 글꼴로 바꾸기 (PDF 가 작아진다) | dist 의 글꼴이 3MB 에서 27MB 로 늡니다. 학교망에서 첫 화면이 느려지는 쪽이 더 큰 손해입니다. |

### 고쳐서 받아들인 것

| 제안 | 어떻게 | 까닭 |
|---|---|---|
| 빌려 온 것을 지문에 | 그림은 읽은 그대로의 값(기본값을 채우기 전)과 파일 내용, 카드는 차례까지 넣음 | 형식에 기본값이 새로 생겨도 지문이 바뀌지 않아야 하고, 덱에서 카드의 차례가 바뀌면 찍히는 쪽이 달라집니다. |
| 공개 조건 4 를 `publishGaps()` 가 알려 주기 | 가리키는 묶음이 초안인 것과, 공개되었다가 공개 조건을 잃은 것을 따로 알려 줌. 묶음 사이 검사는 공개 조건을 보지 않고 읽음 | 지문을 묻는 함수가 앞 묶음의 검수 상태 때문에 멈추면 다시 서명할 수 없습니다. |
| 베끼기 검사 기록의 `by` | pass 만 `copy-guard@<8자>` 여야 침. fix 는 누가 적어도 침 | 짜임이 겹친다는 것은 사람이 찾아 적습니다. |
| 직접 찍은 사진의 `credit.note` | AI 로 만든 그림에는 묻지 않음 | 찍은 사람이 없습니다. |
| 큰 수 대조 (`70만`) | `\d+[천만억]+` 를 세 자리 숫자보다 먼저 봄 | "100만"이 "100"으로 읽히면 "100명"과 구분되지 않습니다. |
| 연표의 `when` 을 글로 보기 | `NOT_PROSE` 에서 빼고, 만들기 세트의 `when`(선택값)은 `NOT_PROSE_AT` 에 경로로 적음 | 같은 이름의 칸이 한쪽은 글이고 한쪽은 선택값입니다. |
| PDF 캐시의 입력 | G 의 것에 `scripts/render-pdf.mjs` 와 `package-lock.json` 을 더함 | 찍는 도구가 바뀌어도 다시 찍어야 합니다. |
| 공개된 차시를 고친 뒤의 오류 문구 | 검수 기록이 낡았을 때만 "draft 로 되돌립니다"를 붙임 | 처음 공개하려다 기록이 모자란 사람에게는 맞지 않는 말입니다. |

### 검토에 없었지만 더한 것

- `pdfjs-dist` (devDependency): 계약서가 요구하는 "찍은 PDF 의 쪽수"와 "PDF 의 글" 검사를 할 수 있는 패키지가 없었습니다.
- 페이퍼크래프트는 늘 A4 세로·단면 (형식): 전개도 모듈이 세로 한 쪽(190 × 249mm)에 그립니다.
- 묶음 사이 검사의 오류 문구에도 줄 번호가 붙습니다.
- 배포 요약에 사이트에서 빠지는 묶음도 적습니다 (공개된 차시가 draft 인 채로 합쳐진 것을 승인 전에 봅니다).

## 고친 계약서를 한 번 더 검토하고 정한 것

네 관점이 고친 계약서를 한 번 더 써 보고 낸 문제 열여덟 가지입니다. 하나씩 다시 해 본 뒤에 모두 고쳤습니다. 여기에는 **서로 달랐던 제안 가운데 고른 것**과 **고쳐서 받아들인 것**만 적습니다. 받아들이지 않은 것은 없습니다.

### 서로 달랐던 제안 가운데 고른 것

| 무엇 | 고른 것 | 까닭 |
|---|---|---|
| 공개된 차시를 고칠 때, 그것을 가리키는 공개된 묶음에 할 일을 어디에서 알려 주나 (A·P: 오류 끝에 한 줄을 덧붙인다, M: 남은 것을 알려 주는 문구 자체를 늘린다) | 오류 끝에 덧붙인다. `publishGaps()` 의 문구는 그대로 | `publishGaps()` 는 처음 공개하려는 초안에도 씁니다. 그 사람에게 "draft 로 되돌리라"는 말은 맞지 않습니다 (고친 차시의 안내를 정할 때와 같은 까닭입니다). |
| 가리키는 묶음이 공개 조건을 잃었을 때의 문구 (M: "그 묶음부터 바로잡습니다. 남은 것은 `publishGaps()`", 지금: "그 묶음부터 다시 검수합니다") | M 의 것 | 그 묶음이 고쳐진 것이 아니라 그 묶음이 가리키는 더 앞 묶음이 초안으로 돌아간 것일 수도 있습니다. 그때는 다시 검수할 것이 없습니다. |
| 그 한 줄을 언제 붙이나 (A: 가리키는 묶음이 초안일 때, 고친 차시의 안내와 함께. P: 문구가 "가리키는"으로 시작할 때, 고친 차시의 안내가 없을 때만) | 가리키는 묶음이 초안이거나 공개 조건을 잃었을 때. 이 묶음의 기록도 낡았으면 고친 차시의 안내만 | 두 경우 모두 할 일이 같습니다 (이 묶음도 draft 로). 문구의 첫 낱말이 아니라 가리키는 묶음의 상태로 가립니다. 두 안내를 함께 붙이면 같은 말이 두 번 나옵니다. |

### 고쳐서 받아들인 것

| 제안 | 어떻게 | 까닭 |
|---|---|---|
| `shownMedia(lesson)` | `shownMedia(lesson, 'slides')` 를 더함 | PPTX 마지막 장에는 수업 화면에 실린 그림만 올립니다. 그 가림을 슬라이드 담당이 `mediaUses()` 로 다시 짜지 않게 했습니다. |
| `prepare` 스크립트의 `\|\| true` | `\|\| exit 0` | Windows 의 cmd 에는 `true` 명령이 없어서, git 저장소가 아닌 곳(내려받은 압축 파일)에서 `npm ci` 가 멈춥니다. |
| CC 가 아닌 자료의 `licence_url` 을 막기 (CC0 만 예외) | 저작권 없음(PD)의 `publicdomain/mark` 주소도 받음. 주소 꼴이 아닌 값에는 칸의 문구만 보여 줌 | 위키미디어 공용의 저작권 없는 자료에는 퍼블릭 도메인 마크 주소가 붙어 있습니다. 주소 자리에 "CC BY-SA 3.0" 처럼 이름을 적으면 한국어 문구 대신 TypeError 가 나가고 있었습니다. |
| `SITE_URL` 검사 (`absoluteUrl()`) | `astro.config.mjs` 도 빈 값을 주지 않은 것으로 보고, 주소 꼴이 아니면 같은 문구로 멈춤 | 빌드는 `absoluteUrl()` 에 닿기 전에 Astro 의 "Invalid URL" 한 줄로 멈추고 있었습니다. |
| 첫 장은 표지 | 형식이 막고, 표지에 `footerNotice()` 를 찍는 것은 화면과 PPTX 가 같다고 8절에 적음 | 두 산출물을 같은 담당이 만들고, 명세의 한 장이 화면 한 장이자 PPTX 한 장입니다. |
| 공개 빌드에 초안이 섞였는지 보는 산출물 검사 | 그대로. 더해서 계약 시험이 일부러 틀린 페이지(`lessonIds()` 로 주소를 만든 것)를 빌드해 `Base.astro` 의 표시(`noindex,nofollow`, `data-draft`)를 확인 | 산출물 검사는 저장소 담당이 만듭니다. 그 검사가 기대는 표시는 계약 파일이 내므로 계약 시험이 지킵니다. |
| 넘침 조건을 머리·바닥글까지 | 그대로. 공개된 차시의 바닥글(주소가 든 두 줄)이 6mm 에 들어가는 것을 세로·가로에서 재어 봄 | 넓힌 조건이 멀쩡한 쪽을 막으면 안 됩니다. |

### 검토에 없었지만 더한 것

- `tests/contract/setup.test.ts`: `qrcode` 를 형식과 함께 가져다 씁니다. 함께 쓰는 패키지의 형식 선언이 빠지면 `npm run typecheck` 가 실패합니다.
- 기여 문서(17절)의 CONTRIBUTING 에 ⑦ 공개된 차시를 고칠 때의 순서를 더했습니다.

## 마지막 검토에서 정한 것

네 관점이 모두 "이대로 만들기 시작해도 된다"고 한 뒤에 남긴 문제 스물다섯 가지와, 계약을 고친 쪽이 물은 여섯 가지입니다. 문제는 하나씩 다시 해 본 뒤에 모두 고쳤고, 고칠 때마다 계약 시험을 더했습니다. 여기에는 **물음에 정한 것**, **고쳐서 받아들인 것**, **검토에 없었지만 더한 것**만 적습니다. 받아들이지 않은 것은 없습니다.

### 물음에 정한 것

| 물음 | 정한 것 | 까닭 |
|---|---|---|
| 첫 공개 전에 조인 규칙(첫 장은 표지 등)에도 `schema_version` 을 올리나 | 올리지 않는다 | 공개된 명세가 아직 없습니다. 시험용 명세와 고인돌 초안은 모두 새 규칙에 맞습니다. |
| 표지의 `footerNotice()` 를 PPTX 에도 찍나 | 화면과 PPTX 둘 다 | 명세의 한 장이 화면 한 장이자 PPTX 한 장입니다. |
| `npm ci` 가 `.githooks` 를 누구에게나 켜도 되나 | 켠다. 대신 올리기 전 검사는 비공개 자료가 없는 기여자를 막지 않는다 | 아래 '고쳐서 받아들인 것'의 올리기 전 검사. |
| 공개된 묶음 하나가 어긋나면 `npm run dev` 가 통째로 멈추는 것 | 그대로 둔다 | 오류 문구가 어느 묶음에 무엇을 할지 이미 알려 줍니다. |
| 첫 화면에 학기 타일·찾기·검색 상자가 함께 있는 것 | 검색 상자는 첫 화면에 둔다. 배치는 사이트 담당이 정한다 | 화면의 짜임은 계약서가 정하지 않습니다. |
| 뒤 차시의 낱말이 앞 차시의 글에 나오는 것 (낱말 검사) | 이 판에서는 실패가 아니라 알림 | 이 판에서는 알림으로 두기로 했습니다. 실패로 바꿀지는 다음 판에서 정합니다. |

### 고쳐서 받아들인 것

| 제안 | 어떻게 | 까닭 |
|---|---|---|
| 지문을 낼 때 숫자를 글로 바꾸고 글의 앞뒤 빈칸을 뗀다 (A) | 지문을 형식이 읽은 값으로 낸다 (명세에 적은 칸만). `lessonSeal()` 도 숫자와 빈칸을 스스로 맞춘다 | 제안대로면 따옴표 없는 묶음 id(`01`)가 남습니다. 형식이 읽은 값으로 내면 형식이 같은 값으로 받는 것은 모두 같은 지문이 됩니다. 적지 않은 칸의 기본값은 여전히 들지 않습니다. |
| 그림을 빌드 뒤에 dist 로 복사하고 자리는 `DIST_DIR` 로 (G) | 차례는 그대로 받고, 자리는 `--out <폴더>` 인자와 `DIST_DIR` 을 `distDir()` 하나가 읽는다 | 네 스크립트가 같은 인자를 저마다 다르게 읽지 않게 했습니다. |
| 올리기 전 검사: 비공개 자료가 없으면 `npm run check` 만 돌리고, 그런 PR 은 CI 가 실패한 채로 열린다 (M) | 비공개 자료가 없으면 한 줄 알리고 지나간다. 막는 곳은 기본 가지의 CI 와 CODEOWNERS 승인이고, PR 의 CI 는 알림만 한다 | 기여자가 만들 수 없는 기록 때문에 올리기가 막히거나 PR 이 실패한 채로 열리지 않게 했습니다. |
| 카드의 놀이 방법을 안내 페이지와 단원 페이지에 (A) | 안내 페이지의 카드 줄 아래에만 | 단원 덱의 놀이 방법은 단원 정리 묶음의 안내 페이지에 보입니다. 같은 글을 두 페이지가 따로 그리지 않습니다. |
| 사실 대조표에 찍을 글 묶음 `factBoxes()` (P) | 글 뽑기(`childStrings()`·`teacherStrings()`)의 경로에서 상자를 만든다. 문항은 틀린 보기까지 들고, 진행 메모·준비물·인쇄 안내도 상자가 있다 | "아이와 교사가 읽는 글은 빠짐없이 표에 오른다"는 말을 시험이 지키게 했습니다. 제안의 코드로는 틀린 보기, 수업 화면의 진행 메모, 준비물이 표에 오르지 않았습니다. |
| 넘침 조건에 '상자 밖으로 나간 요소'와 '싣지 못한 그림'을 더한다 (G) | 그대로. 재는 본보기를 계약 시험(`tests/contract/print.test.ts`)에 둔다 | 찍는 쪽(인쇄물)과 다시 보는 쪽(저장소)이 같은 조건을 같은 뜻으로 읽게 했습니다. |
| PDF 의 글은 조각을 그대로 이어 붙여 견준다 (G) | 이어 붙인 뒤 빈칸과 줄바꿈도 뺀다 | 조각 사이와 글자 사이의 빈칸은 글꼴과 줄바꿈에 따라 달라집니다. |

| 바로 가기(심볼릭 링크)인 그림 파일을 막는다 (M) | `fs.realpathSync.native` 로 견준다 | 이름의 대소문자만 다른 파일까지 잡으려면 운영체제가 알려 주는 실제 이름이 있어야 합니다. |

### 검토에 없었지만 더한 것

- `cacheDir()`: `--out` 으로 다른 폴더를 가리킨 실행은 캐시도 그 옆(`<폴더>.cache/`)에 둡니다. 시험용 명세의 묶음 id 가 실제 차시와 같아서, 캐시를 같이 쓰면 시험이 찍은 PDF 가 실제 빌드에 복사되거나 같이 도는 시험이 서로의 `lessons.json` 을 덮어씁니다.
- `tests/contract/helpers.ts` 의 `buildSite()`: 사이트를 `.cache/tests/` 아래에 깨끗한 환경 변수로 빌드합니다. 담당마다 같은 일을 다시 짜지 않게 했습니다.
- 시험용 컬러링 도안을 세로로 긴 것(190 × 249)으로 바꿨습니다. 정사각형 도안으로는 본문을 넘기는 짜임이 시험에 걸리지 않았습니다.
- 앞선 검토에서 미뤄 둔 것 가운데 UTF-8 이 아닌 파일(메모장의 옛 저장 방식)의 안내 문구를 넣었습니다.
