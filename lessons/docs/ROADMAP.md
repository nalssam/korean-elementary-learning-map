# 나중에 만들 것의 밑그림

지금 형식에는 없고, 생성기를 만들 때 함께 정할 것들입니다. 여기 적힌 꼴은 **계획**이지 약속이 아닙니다. 만드는 사람이 써 보고 고칩니다. 꼴을 정하면 `schema/`, 주소, 담당을 한 번에 더합니다 (`docs/CONTRACT.md` 18절).

## 1. 방탈출

지금은 `assets.escape` 에 skip·planned 만 적습니다. 편성표의 방탈출 30편 가운데 퀴즈만으로 되는 것은 없습니다. 읽고 답하기 13, 짝 맞추기 11, 지도에서 찾기 6, 차례 맞추기 6편입니다. 그래서 퍼즐은 퀴즈 문항 번호가 아니라 아래 넷 가운데 하나로 잡습니다.

```ts
/** 퍼즐: 퀴즈 문항 / 읽기 자료를 읽고 퀴즈 문항에 답하기 / 이 묶음의 웹 활동 그대로 / 활동을 바로 적기 */
const Puzzle = z.discriminatedUnion('kind', [
  so({ kind: z.literal('quiz'), item: z.number().int().min(1) }),
  so({ kind: z.literal('read'), passage: Slug, item: z.number().int().min(1) }),
  so({ kind: z.literal('web_activity') }),
  // sort | match | order | place: 웹 활동과 같은 꼴
]);

/** 방. 차시용은 방 하나, 단원 정리용은 다섯까지 */
const Room = so({
  title: T(20).optional(),
  /** 이 방을 풀면 얻는 글자·숫자. 방들의 key 를 차례로 이으면 마지막 자물쇠의 답이다. */
  key: T(4).optional(),
  /** 같은 단원 앞 묶음의 방탈출 퍼즐을 그대로 가져온다 (단원 정리 묶음에서만). 예: ["02", "03-04"] */
  from: z.array(BundleId).max(3).default([]),
  puzzles: z.array(Puzzle).max(4).default([]),
});

escape: opt({ title: T(30), minutes: z.number().int().min(5).max(40), rooms: z.array(Room).min(1).max(5), print: PrintSpec.optional() })
```

함께 정할 것:

- 주소 `/<id>/escape/` 와 담당(활동). `print` 가 있으면 단서지를 `/<id>/escape/print/` 와 `escape.pdf` 로도 냅니다 (인쇄물의 틀을 씁니다).
- `lib/content.ts` 에 `escapeRooms(lesson)`: `from` 을 풀어 앞 묶음의 퍼즐을 먼저, 이 묶음의 퍼즐을 뒤에 놓습니다. 로더는 `from` 이 같은 단원의 앞 묶음이고, 그 묶음의 방탈출이 ready 이며, no_play 차시가 아닌지 봅니다 (단원 카드 덱의 `collect` 와 같은 규칙).
- 피해를 담은 사실은 퍼즐이 가리킬 수 없습니다 (지금 퀴즈·카드·웹 활동에 거는 규칙 그대로). `scored()` 가 false 인 차시의 방탈출은 시간 재기와 순위를 쓰지 않습니다.
- no_play 차시에는 방탈출을 만들지 않습니다 (지금도 planned 조차 막습니다).
- 기존 저장소(mdbf2026)의 방탈출 엔진(퍼즐 다섯 가지: 문서·짝 맞추기·지도·순서·OX)을 옮길 때는 그림의 권리를 먼저 점검합니다.

## 2. 3D·가상 체험

지금은 `assets.virtual3d` 에 skip·planned 만 적습니다. 5학년 2학기에 계획된 것은 단원마다 하나, 모두 셋입니다 (석굴암, 앙부일구, 3단원 하나).

```ts
/** 우리가 만든 3D 는 module, 바깥 자료는 url. 둘 가운데 하나만 */
virtual3d: opt({ title: T(30), module: Slug.optional(), url: Url.optional(), how: z.array(Text).min(1) })
```

함께 정할 것:

- 주소 `/<id>/3d/` 와 담당(활동). 우리가 만든 장면은 `src/components/play/scenes/<module>.ts` 에 둡니다. 전개도 모듈처럼 "그 차시에만 맞는 코드"가 허용되는 두 번째 자리가 됩니다.
- 바깥 자료(`url`)는 사이트 밖으로 나가는 링크라서 학생 페이지에 두지 않고 차시 안내 페이지에만 겁니다. "외부 요청을 하지 않는다"는 약속과 부딪히지 않게, 끼워 넣지 않고 링크로만 엽니다.
- 3D 엔진은 새 의존성입니다. 학교망과 낮은 사양 기기에서 도는지 먼저 시험합니다.

## 3. 그 밖에 미뤄 둔 것

- **묶음마다의 성취기준.** 지금은 단원에만 적혀 있습니다. 묶음과 성취기준의 짝을 확인하면 차시표의 `bundles[].standards` 에 적습니다 (형식은 이미 받습니다).
- **영상.** 띄우는 장과 생성기를 만들 때 `media.kind` 와 큰 파일을 두는 곳(저장소 밖)을 함께 정합니다.
- **공공누리 제0유형.** 있는지 확인되면 `Licence` 에 더합니다.
- **묶음을 다시 나눌 때의 옛 주소.** 차시표에 옛 id 를 적는 선택 칸을 더해 넘기는 페이지를 만듭니다.
- **주석까지 묶는 베끼기 검사 기록.** 지금 지문은 값만 보고 주석은 올리기 전 검사가 다시 봅니다 (`docs/CONTRACT.md` 13절). 주석의 베끼기를 CI 에서도 막아야 하면, 베끼기 검사 기록에만 주석을 넣은 지문을 따로 두는 길이 있습니다 (다른 검수 넷의 지문은 그대로 둡니다).
- **출처 주소 살아 있는지 보기.** 주마다 `--online` 검사로 주소가 열리고 근거 구절(`quote`)이 그대로 있는지 봅니다.

## 4. PPTX 에 심은 글꼴의 무게

GitHub Pages 는 사이트 하나를 1GB 까지 받습니다 (`checks/outputs.mjs` 의 한도 1000MB). 수업 화면 PPTX 에는 Pretendard 보통·굵게 두 벌을 통째로 심습니다 (`generators/pptx/embed.py`. 교사가 고쳐 쓴 글자도 같은 글꼴로 보이게 하려는 것입니다). 2026-11-19 에 고인돌 초안(`5-2/1/01`)의 미리 보기 빌드로 잰 값입니다.

| 무엇 | 크기 |
|---|---|
| `slides.pptx` 하나 | 3.66MB |
| 그 안의 글꼴 두 벌 (압축된 채) | 2.36MB (64%) |
| 그 안의 그림 아홉 장 | 1.20MB |
| PDF 넷 (학습지 0.92MB, 페이퍼크래프트 0.35MB, 카드 0.25MB) | 1.53MB |
| 그림 (`/media/5-2/1/01/`) | 0.85MB |
| 페이지 (`/5-2/1/01/` 아래 HTML) | 0.17MB |
| **묶음 하나 모두** | **6.21MB** |
| 모든 묶음이 함께 쓰는 것 (`_astro/` 3.09MB, 인쇄 글꼴 3.91MB, 검색 색인 0.62MB) | 7.6MB |

묶음 250개(3~6학년 여덟 학기)로 늘려 어림하면 PPTX 의 글꼴만 589MB, 사이트 전체는 1,551MB 남짓으로 한도를 넘습니다. 글꼴을 빼도 962MB 라 넉넉하지 않습니다 (PPTX 안의 그림이 `/media/` 의 그림과 겹치고, 사진이 든 학습지 PDF 가 큽니다).

고를 수 있는 길과 묶음 250개일 때의 사이트 크기입니다.

| 길 | 사이트 | 잃는 것 |
|---|---|---|
| 보통 굵기만 심는다 | 1,255MB | 굵은 글은 PowerPoint 가 보통 굵기를 굵게 흉내 내어 그립니다. 그래도 한도를 넘습니다. |
| 그 PPTX 에 쓴 글자만 남긴다 (고인돌 초안은 391자, 두 벌 합쳐 0.09MB) | 985MB | 교사가 새로 쓴 글자 가운데 없는 것은 다른 글꼴로 보입니다. 한글 음절 11,172자를 모두 남기면 한 벌에 0.94MB 라 거의 줄지 않습니다. |
| PPTX 를 저장소의 릴리스 파일로 올린다 | 637MB | 내려받기 링크가 사이트 밖(github.com)으로 나갑니다. 배포 워크플로가 릴리스도 맡아야 합니다. |
| 글꼴을 심지 않는다 | 962MB | Pretendard 가 없는 컴퓨터에서는 맑은 고딕 같은 글꼴로 바뀌어 글 폭이 달라지고 넘칠 수 있습니다. |

정하는 때: 첫 시범 단원(5-2 1단원)을 다 만든 뒤, 그 단원의 실제 크기로 다시 재고 정합니다. 그 전에는 지금처럼 두 벌을 통째로 심습니다.

## 5. 차시마다 만드는 자료

차시 안내 페이지에는 ready 인 자료만 보입니다. 앞으로 나올 자료는 이 표에서 봅니다. 묶음마다의 계획(`assets.<종류>.idea`)과 만들지 않는 까닭(`reason`)은 그 묶음의 `lesson.yaml` 에 있습니다. 수업 화면·학습지·확인 퀴즈는 모든 묶음에 있어서 표에 넣지 않습니다.

| 묶음 | 페이퍼크래프트 | 컬러링 도안 | 만들기 세트 | 방탈출 | 3D·가상 체험 | 웹 활동 | 카드 |
|---|---|---|---|---|---|---|---|
| 5-2/1/01 이 큰 돌, 누가 어떻게? (초안) | 있음 | 만들 예정 | 만들지 않음 | 만들 예정 | 만들지 않음 | 있음 | 있음 |

차시표의 나머지 31개 묶음은 아직 명세가 없습니다. 명세를 더하는 PR 에서 이 표에 한 줄을 더합니다.

## 6. 페이퍼크래프트를 늘리는 길

지금 전개도는 모형마다 손으로 쓴 모듈입니다 (`generators/papercraft/modules/<module>.ts`, 고인돌은 436줄). 선·풀칠 자리·글자 맞추기는 `generators/papercraft/net.ts` 가 함께 맡지만, 조각의 꼴과 배치는 모듈마다 새로 씁니다. 묶음 250개에 모형이 수십 개 붙으면 모듈마다 같은 계산을 되풀이하고, 고칠 때마다 그 차시를 다시 검수합니다 (모듈 파일은 그 차시의 지문에 듭니다).

계획은 자주 쓰는 꼴을 치수만 받는 함수로 `net.ts` 옆에 두는 것입니다.

- 상자(덮개돌·받침돌·건물 몸체), 쐐기(흙 비탈·지붕), 원기둥(기둥·탑), 뿔(지붕 끝), 바닥판(자리 표시만 찍는 판).
- 모듈은 "어떤 꼴을 몇 mm 로, 어느 쪽에 무슨 이름표를" 적는 짧은 파일이 됩니다. 그 차시에만 맞는 그림(돌결, 기와 무늬)은 모듈에 남깁니다.
- 꼴 함수는 함께 쓰는 코드라 차시의 지문에 들지 않습니다. 고치면 시험(`tests/papercraft/`)과 미리 보기 빌드로 모든 모형을 다시 봅니다 (`docs/CONTRACT.md` 12절).
- 두 번째 모형을 만들 때 고인돌 모듈에서 상자와 쐐기를 떼어 내 시작합니다. 한 모형만 보고 꼴 함수를 미리 만들지 않습니다.

## 7. 수업 화면과 PPTX, 만들기 시간

세 번째 검수(2026-11-19)에서 이번 판에는 넣지 않고 미뤄 둔 것입니다.

- **발표자 창.** 수업 화면을 두 창으로 띄웁니다. 교실 화면에는 장만, 교사의 노트북에는 교사 메모와 다음 장을 보여 줍니다. 두 창은 같은 장 번호를 따라갑니다 (같은 컴퓨터 안에서 `BroadcastChannel` 로 주고받고, 바깥으로는 아무것도 보내지 않습니다). 지금은 한 창에서 메모 창을 열면 장을 메모 창 위의 자리로 줄여 그립니다 (`docs/CONTRACT.md` 8절).
- **PPTX 의 QR.** 웹 수업 화면은 QR 창으로 확인 퀴즈와 웹 활동의 QR 을 띄웁니다. PPTX 에는 아직 없습니다. 넣는다면 `Qr.astro` 와 같은 주소(`absoluteUrl()`)와 같은 오류 복원 수준(M)으로 PNG 나 도형을 만들어 마지막 장 앞에 한 장을 둡니다. 미리 보기 빌드에서는 주소가 127.0.0.1 이 될 수 있으므로 공개 빌드에서만 넣습니다.
- **PowerPoint 와 한컴 한쇼에서 열어 보기.** `slides.pptx` 는 지금까지 LibreOffice(soffice)로 PDF 로 바꿔 그려 본 것뿐입니다. 그렇게 확인한 것: 장마다 글이 틀 밖으로 넘치지 않는다, 그림이 늘어나거나 잘리지 않는다, 출처 장이 앞 장을 채운 뒤에 열린다. 확인하지 못한 것: PowerPoint 와 한쇼에서 심은 Pretendard 가 실제로 쓰이는지, 글 조각의 언어(`ko-KR`)가 맞춤법 밑줄을 없애는지, 줄바꿈과 글 폭이 LibreOffice 와 같은지, 메모란이 그대로 보이는지. 날쌤이 Windows 의 PowerPoint 와 한쇼에서 고인돌 초안의 PPTX 를 열어 장마다 보고, 어긋난 장을 번호와 함께 남은 일로 올립니다.
- **종이 고인돌 만드는 시간 재기.** 차시 안내 페이지에 찍힌 만드는 시간은 어림한 값입니다. 날쌤이나 기여자가 인쇄한 세트 하나를 실제로 오리고 접고 붙여 걸린 시간을 재고(어른 한 사람, 5학년 모둠 하나), 그 값으로 명세의 시간을 바꿉니다. 재기 전까지는 “~걸릴 수 있습니다”로 둡니다 (`docs/CONTRACT.md` 15절).
